# Tencent EdgeOne implementation plan

Goal: deploy the complete multi-account Words application on EdgeOne Makers, with MySQL 8 persistence. Branch codex/tencent-edgeone; main remains Cloudflare.

Architecture: Python Flask catch-all under cloud-functions/api; static build output under dist/edgeone. Every API verifies signed cookies. A shared account directory assigns random immutable UIDs; each UID maps to a fixed set of MySQL tables. SQL parameters remain bound, table identifiers derive only from validated server-issued UIDs. A per-user MySQL connection lock serializes business transactions. Tencent assessment releases the lock during network I/O, then stores its result in a new transaction. No learning data on ephemeral disk.

Tech: Python 3.10, Flask, PyMySQL, MySQL 8 InnoDB; native browser frontend.

- [x] Add integration tests requiring a disposable MySQL database. Verify two accounts, failed login, CSRF, imports, answers, retry idempotency, dictation, rollback, concurrent reward spending, assessment and persistence.
- [x] edgeone/storage.py: canonical MySQL schema and parameterized SQLite-compatible query facade; scoped table names; UTC SQL sessions; serialized transactions. Fail closed on missing DB configuration. TLS verified by default.
- [x] edgeone/server.py: Flask auth routes, per-account API dispatch, explicit origin configuration, environment-only Tencent credentials. Keep initial books immutable and seed only on first use; no reset of ongoing assessment on later requests.
